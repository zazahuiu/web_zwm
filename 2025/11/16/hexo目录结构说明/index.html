hexo目录结构说明

Hexo 目录结构说明+备份恢复清单

这份清单清晰区分「核心需备份文件」「自动生成文件」，帮你快速搞定数据迁移、项目重置，避免误删关键内容或残留无用文件。

一、Hexo 核心目录结构（按重要性排序）

目录/文件 作用说明 是否需要备份 备注
source/_posts/ 存放所有 Markdown 文章（含 Front-matter），是博客核心数据 ✅ 必须备份 文章、草稿都在这里，删除后无法恢复
_config.yml 全局配置文件（站点信息、插件配置、主题设置、部署规则等） ✅ 必须备份 核心配置，重置项目后需恢复关键参数
themes/ 博客主题文件夹（默认 landscape，或自定义主题如 next/butterfly） ✅ 按需备份 若修改过主题代码（如样式、模板）则备份；未修改可后续重新安装主题
source/ 下其他文件 如 about/（关于页）、images/（静态图片）、CNAME（自定义域名）等 ✅ 按需备份 非 _posts 目录的自定义内容，根据自己的使用情况备份
package.json 项目依赖配置（记录安装的插件、Hexo 版本） ⚠️ 可选备份 可备份用于快速还原依赖，也可重置后重新安装插件
node_modules/ 依赖包文件夹（npm 安装的插件、Hexo 核心程序） ❌ 无需备份 自动生成，可通过 npm install 重新安装
public/ 生成的静态文件（HTML、CSS、JS 等） ❌ 无需备份 执行 hexo generate 自动生成，清理后可重新生成
db.json Hexo 缓存文件（存储文章元数据、插件缓存） ❌ 无需备份 执行 hexo clean 会删除，自动重建
.deploy_git/ 部署缓存文件夹（Git 部署时生成） ❌ 无需备份 部署时自动生成，可删除后重新部署
package-lock.json 依赖版本锁定文件 ❌ 无需备份 npm install 时自动生成，确保依赖版本一致
scaffolds/ 文章模板文件夹（新建文章时的默认模板） ⚠️ 按需备份 若修改过模板（如自定义 Front-matter）则备份，默认模板无需备份

二、备份操作步骤（按优先级）

  1. 新建备份文件夹（如 hexo-blog-backup-2025），避免与项目文件混淆；
  2. 复制「必须备份」的内容：
    • 完整复制 source/_posts/ 文件夹到备份目录；
    • 复制 _config.yml 文件到备份目录（重命名为 _config-backup.yml 更易区分）；
  3. 复制「按需备份」的内容：
    • 若修改过主题，复制 themes/ 文件夹到备份目录；
    • 复制 source/ 下的自定义文件夹（如 about/、images/）；
    • 若需快速还原依赖，复制 package.json 到备份目录；
  4. 备份完成后，可将备份文件夹压缩（如 ZIP 格式），避免误操作。

三、恢复操作步骤（项目重置后）

  1. 完成 Hexo 项目初始化（hexo init .）和基础插件安装；
  2. 恢复核心配置：
    • 打开备份的 _config-backup.yml，复制关键配置到新生成的 _config.yml 中，重点关注：
      • 站点信息：title、author、language、timezone；
      • 部署配置：deploy 节点（Git 仓库地址、分支）；
      • 主题配置：theme（确保与备份的主题名称一致）；
      • 路径配置：source_dir、public_dir 等（默认无需修改）；
    • 注意：不要直接覆盖 _config.yml，避免丢失 Hexo 初始化的默认插件配置；
  3. 恢复文章和自定义内容：
    • 将备份的 source/_posts/ 文件夹复制到新项目的 source/ 下，覆盖默认的 _posts；
    • 将备份的 themes/ 文件夹复制到新项目根目录，覆盖默认主题；
    • 复制 source/ 下的自定义文件夹（如 about/、images/）到新项目的 source/ 下；
  4. 还原依赖（若备份了 package.json）：
    • 将备份的 package.json 替换新项目的 package.json；
    • 执行 npm install，自动安装所有依赖（无需手动逐个安装插件）；
  5. 验证恢复结果：
    • 执行 hexo clean && hexo generate --debug，查看 public 目录是否生成所有页面；
    • 执行 hexo server，本地访问 http://localhost:4000 确认博客正常显示。

四、注意事项

  1. 备份时优先保留「自己创建/修改」的文件，自动生成的文件（如 node_modules、public）无需备份；
  2. 恢复配置时，若使用自定义主题，需确保 _config.yml 中的 theme 配置与主题文件夹名称一致；
  3. 若备份后安装了新插件，恢复时需在 package.json 中补充新插件名称，或重新执行 npm install 插件名 --save；
  4. 建议定期备份（如发布新文章后），避免因电脑故障、误操作导致数据丢失。
